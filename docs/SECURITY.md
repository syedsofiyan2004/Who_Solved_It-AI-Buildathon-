# Security

## Local showcase controls

- `.env` is ignored and never included in shareable archives.
- The browser never receives `NVIDIA_API_KEY`, AI provider keys, JWT secrets, or database credentials.
- The API uses the normal provider credential chain and sends only approved technical context.
- Passwords are hashed; JWTs are short-lived and validated for issuer, audience, expiry, subject, and token ID.
- Role-based and object-level authorization applies to challenge detail, edits, reviews, profiles, search candidates, contact fields, attachments, feedback, and RAG context.
- Database queries remain parameterized through SQLAlchemy.
- Upload MIME type, size, filename, digest, and pending-scan state are validated.
- Search and authentication endpoints are rate-limited.
- Audit events avoid prompts, completions, passwords, credentials, and private contact data.

## AI boundary

Employee names, emails, job titles, teams, departments, contact details, ownership, verification, roles, and permissions remain structured in PostgreSQL. They are never included in embedding documents and are never generated by the model.

The AI provider receives only authorized technical fields after object authorization. Query and source content are secret-scanned before invocation. Generated output is accepted only when it follows the strict JSON/citation contract and cites only the supplied solution IDs.

## Credential handling

For the local NVIDIA mode:

```env
NVIDIA_API_KEY=your-new-local-key
```

The value belongs only in the ignored local `.env`. It must not appear in source files, Compose defaults, screenshots, logs, exported archives, or chat messages.

## Source-package safety

From the repository root:

```bash
python apps/api/scripts/scan_secrets.py
python apps/api/scripts/package_source.py --output artifacts/minfy-resolve-source.zip
python apps/api/scripts/verify_source_package.py --archive artifacts/minfy-resolve-source.zip
```

The package excludes `.env`, Git metadata, dependencies, builds, virtual environments, uploads, caches, generated TypeScript build files, and detected credentials.

## Showcase data

Technical records are original synthetic examples. They do not contain real customer identifiers, credentials, private IP addresses, private messages, or copied Q&A content. The employee/contact convention is temporary demonstration data and requires organizational approval before real use.

## Production boundary

The final buildathon scope is local-only. Real employee use would additionally require company SSO, a reviewed contact/data-retention policy, attachment malware scanning, TLS, backup/recovery, and security ownership.
