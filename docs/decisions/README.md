# Architecture Decision Records

This directory records proposed and approved changes to the locked architecture. No ADR is approved merely by being created.

## When an ADR is required

Create an ADR before changing the database technology, AI provider, authentication approach, deployment architecture, major UI framework, API contract, repository structure, or search-ranking strategy. Also use one for any change that materially affects data exposure, migration compatibility, or the approved MVP scope.

## File name and template

Use `ADR-NNN-short-kebab-case-title.md` and include:

1. Status and approval owner/date.
2. Problem and current architecture.
3. Proposed change and reason.
4. Alternatives considered.
5. Database, API, UI, security, and operations impact.
6. Migration and rollback plan.
7. Implementation and test implications.

## Current decisions
